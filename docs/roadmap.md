# 07/23 (혼잡도 로직 재검토)

1. 혼잡도를 "실시간" → "예상(예보)"로 전환.
    - 문제: 코스는 미래에 방문할 곳인데 생성 시점의 "현재 혼잡도"로 필터했다. 오후 2시에 저녁 7시
      데이트 코스를 "여유"로 만들면 2시 혼잡도가 붙는 모순. 시간이 지나면 혼잡도는 계속 바뀌는데
      사용자가 선택한 방문 시각과 맞지 않았다.
    - 확인: 서울시 citydata API가 현재값과 함께 12시간 시간대별 예보(FCST)를 같은 응답에 준다.
      실측으로 신뢰성 검증(1.5시간 전 예보 인구수가 실제와 일치, 밤→새벽 단조 감소로 일관성 OK,
      등록 핫스팟 예보 제공률 100%). 코스 추천 정밀도(여유/보통/붐빔)엔 충분.
    - 결정: 각 장소를 그 장소의 "방문 시각"에 맞는 예보 혼잡도로 표시. UI도 "18시 예상 혼잡도: 여유"
      처럼 시각을 함께 노출. 예보 공백(근시간)·12시간 범위 밖은 현재값 폴백, 멀티데이 2일차 이후는 생략.

2. 혼잡도를 "장소 선택"에서 빼고 "정보 표시"로만.
    - 문제: 기존엔 붐비는 장소를 다른 곳으로 교체했는데, ① 틀린 시각(현재) 기준이라 잘못된 교체였고
      ② 혼잡도로 장소가 흔들려 추천 다양성을 해쳤다.
    - 결정: 혼잡도는 장소 선정에 관여하지 않고 순수 정보로만. 장소 선택은 목적·동반·위치로만 결정.
      (프론트 "나만의 코스" 위저드에서 혼잡도 선택 칩을 뺄지는 추후 — 서버는 받아도 무시.)

3. 혼잡도 API 호출 이름 매핑 이슈(발견, 추후 작업).
    - 확인: 혼잡도 API는 등록된 핫스팟 이름과 정확히 일치해야만 응답한다(퍼지 매칭 없음).
      "강남"은 실패하고 "강남역"이 정답 — 역 이름이 곧 그 동네 핫스팟이라 역을 떼면 오히려 호출이 깨진다.
    - 문제: 임베딩 장소 180개 중 약 절반(88개)이 area 이름이 비어 혼잡도를 아예 못 부른다.
      → "역 떼기"가 아니라 각 장소를 서울시 등록 핫스팟 정식 이름에 매핑하는 작업이 필요.

4. seoul_places.json 정리(장소·식당 다양성 목적, 진행 예정).
    - 완전 중복 1건(노들섬 scene) + 같은 장소 다른 이름 3쌍(노들섬/N서울타워/어린이대공원) 통일.
    - 위 3번 area 이름 매핑을 함께 채운다.
