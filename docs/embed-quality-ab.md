# 임베딩 데이터·프롬프트 개선 A/B 측정 (2026-07-27)

원천 데이터 정제와 프롬프트 수정을 같은 날 함께 진행했다. 둘의 효과가 섞이지 않게
**4 arm**으로 나눠 측정했다.

| arm | 데이터 | 프롬프트 | 벡터 컬렉션 |
|---|---|---|---|
| ① 기준선 | 865곳 (개선 전) | 개선 전 | 구 `seoullo` |
| ② 데이터만 | **816곳 (개선 후)** | 개선 전 | `seoullo_v2` |
| ③ | **816곳 (개선 후)** | **개선 후** | `seoullo_v2` |
| ④ 현재 | **816곳 (개선 후)** | **개선 후 + 다양성 규칙 수정** | `seoullo_v2` |

①→② 가 데이터 기여분, ②→③ 이 프롬프트 기여분, ③→④ 가 3절 회귀 수정분이다.

**측정 조건** — 페르소나 10개(로컬/여행자 × 동반 × 목적 × 권역 조합), `run_course` 직접 호출로
HTTP 우회, arm당 약 135초. 프롬프트 arm 은 `course.py`·`schema.py` 를 통째로 바꿔치기해
생성 코드까지 포함해 되돌렸다.

## 1. 데이터 품질 (정적 지표 — LLM 불필요)

| 지표 | 개선 전 (865) | 개선 후 (816) | |
|---|---:|---:|---|
| 설명 40자 미만 | 314 | **0** | −314 |
| 템플릿 설명 (`~명소예요.`) | 46 | **0** | −46 |
| ragText 280자 초과 (후보 줄에서 잘림) | 156 | **17** | −139 |
| 서울 좌표 범위 밖 | 3 | **0** | −3 |
| 이름 포함 중복쌍 | 117 | **90** | −27 |
| 사람이 검수한 문서 | 2 | **107** | +105 |
| ragText ↔ 필드 정합성 위반 | 0 | 0 | — |
| 설명 평균 길이 | 101자 | 95자 | −6 |
| **코퍼스 고유 어휘 수** | 9,963 | **5,036** | **−49%** |

마지막 줄만 하락이고, 해석이 필요하다.

```
총 토큰       20,145 → 19,920   (거의 동일)
코퍼스 고유어   9,963 →  5,036   (반토막)
문서당 고유어    22.2 →   23.6   (오히려 증가)
```

문서 하나하나는 오히려 조금 더 풍부해졌는데 코퍼스 전체 어휘는 절반이다. 문서들이 서로
훨씬 많은 단어를 공유한다는 뜻 — 설명을 `{이름}은 {정체}로 {특징}을 볼 수 있고, {시설}이
있어요` 형식으로 통일한 대가다. **검색 변별력 손실 우려는 아래 3-2에서 실측으로 반박된다.**

## 2. 응답 품질 4 arm 비교

| 지표 | ① 기준선 | ② 데이터만 | ③ | ④ 현재 | 데이터 효과 | 프롬프트 효과 |
|---|---:|---:|---:|---:|---:|---:|
| **200m내 스톱쌍 %** | 24.6 | 9.3 | 6.8 | **5.6** | **−15.3pp** | −3.7pp |
| **광고성 수식 / 1만자** | 26.4 | 25.6 | 10.1 | **11.5** | −0.8 | **−14.9 (−56%)** |
| **실용어 / 1만자** | 137.3 | 135.3 | 212.4 | **198.0** | −2.0 | **+60.7 (+44%)** |
| 대분류 1종 코스 % | 60.0 | 60.0 | 50.0 | **50.0** | 0 | −10.0pp |
| 대분류 종류 / 코스 | 1.6 | 1.5 | 1.7 | **1.6** | −0.1 | 0 |
| 삭제된 장소 등장 | 1 | **0** | 0 | **0** | −1 | 0 |

| reason 평균 길이 | 51.8 | 59.2 | 55.8 | **62.6** | +7.4 | +3.4 |

| **하루 평균 스톱** | 3.9 | 3.8 | 3.4 ⚠ | **3.8** | −0.1 | 0 |

### 2-1. 데이터 개선이 만든 것 — 지리적 응집

**200m내 스톱쌍이 24.6% → 9.3% 로 62% 감소**했다. 프롬프트를 전혀 안 바꾼 상태에서
나온 변화라 온전히 데이터 기여분이다. 원인은 두 가지로 본다.

- 중복·저가치 레코드 49곳 제거 (야경 변형 11, 복합명 4, 관광안내소 13, 프로그램 2, 기타 19)
- 설명이 채워지면서(40자 미만 314→0) 의미 유사도가 제 역할을 하게 됨

`서초 여행자 지원센터` 가 arm ①에서 코스 스톱으로 뽑혔다가 ②·③·④에서 사라진 것이
데이터 정제 효과를 그대로 보여준다.

### 2-2. 어휘 반토막은 회수율을 깎지 않았다

1절의 우려(고유 어휘 −49%)와 달리 **AI 선정률이 90% → 100% 로 올랐고**, 후보를 못 채워
폴백으로 빠진 코스가 없었다. 형식 통일이 검색 변별력을 해쳤다는 증거는 나오지 않았다.
오히려 설명이 채워진 효과가 더 컸다.

### 2-3. 프롬프트 개선이 만든 것 — 문체 전환

광고성 수식은 프롬프트를 바꾼 arm ③에서만 급감했다. 데이터만 바꾼 arm ②는 기준선과
사실상 같다(26.4 → 25.6). **문체는 데이터가 아니라 프롬프트가 결정한다**는 것이 분리 측정으로
확인됐다.

| 단어 | ① | ② | ③ |
|---|---:|---:|---:|
| 감성 | 17 | 17 | **9** |
| 설렘 | 6 | 3 | **0** |
| 여운 | 5 | 6 | **0** |
| 특별한 추억 | 0 | 2 | **0** |
| 합계 | 30 | 28 | **9** |

(arm ④ 는 합계 기준 ③ 과 같은 수준 — 11.5/1만자)

같은 페르소나(연인·데이트·홍대)의 출력 변화가 가장 직관적이다.

```
① 감성 쇼핑부터 버스킹까지, 둘만의 밤을 완성하는 코스
   해 질 무렵부터 시작되는 이 코스는 연인과 손을 맞잡고 천천히 걸으며
   둘만의 밤을 채워가는 여정이에요…

③ 합정 출발, 소담상회 전시 관람 후 연남동 산책과 경의선숲길 야경
   합정에서 한강 인근 상권을 둘러보며 밤 데이트를 시작해요. 지하철역 인근을
   산책하며 주변 분위기와 이동 동선을 익히고, 도보로 소담상회로 이동해요.
   19시부터 20시까지 수공예품 쇼핑과 전시 공간을 관람하며…
```

시각·이동수단·순서가 들어간 안내문으로 바뀌었다. 실용어 밀도 +44% 가 이 변화를 수치화한다.

## 3. 확인된 회귀 — 다양성 규칙이 스톱 수를 깎는다 ⚠

arm ③에서 **하루 평균 스톱이 3.9 → 3.4 로 줄었다.** 페르소나별로 보면 원인이 분명하다.

| 페르소나 | ① | ② | ③ | 목표 |
|---|---:|---:|---:|---:|
| P02 로컬·부모님·문화생활·종로 | 4 | 4 | **2** | 4 |
| P10 여행자·혼자·역사·종로 | 4 | 3 | **2** | 4 |
| P01 로컬·혼자·힐링·종로 | 4 | 4 | **3** | 4 |

전부 **종로 문화·역사 계열**이다. 후보가 `문화` 대분류로 쏠린 상황에서, 새로 넣은 규칙

> 같은 날 스톱은 대분류가 2종 이상 섞이게 할 것 — 같은 대분류만 3곳 이상 연달아 넣지 말고,
> 후보에 다른 대분류가 아예 없을 때만 예외로 한다.

이 **"하루 정확히 N곳"** 지시와 충돌했고, LLM 이 개수를 포기하는 쪽을 택했다.
"후보에 다른 대분류가 없을 때만 예외" 라는 안전장치는 작동하지 않았다 — 후보 풀에는
다른 대분류가 **있었지만** 지리·시간 제약과 겹치면서 LLM 이 스톱을 줄여 버렸다.

대분류 1종 코스 비율도 60% → 50% 로 10pp 개선에 그쳤다. **효과는 작고 부작용은 크다.**

### 조치 — arm ④ 로 해소됨

개수를 하드 제약, 다양성을 소프트 선호로 재배치했다.

```
③  같은 날 스톱은 대분류가 2종 이상 섞이게 할 것 … 후보에 다른 대분류가 없을 때만 예외.
④  스톱 개수({count}곳)를 먼저 정확히 채운 뒤, 그 안에서 가능한 한 대분류를 섞어라.
    … 개수를 줄여서 다양성을 맞추지 말 것 — 개수가 먼저다.
```

| 페르소나 | ① | ③ | **④** | 목표 |
|---|---:|---:|---:|---:|
| P01 로컬·혼자·힐링·종로 | 4 | 3 | **4** | 4 |
| P02 로컬·부모님·문화생활·종로 | 4 | 2 | **4** | 4 |
| P10 여행자·혼자·역사·종로 | 4 | 2 | **3** | 4 |

하루 평균 스톱이 3.4 → **3.8** 로 회복됐고(기준선 3.9), 200m내 스톱쌍은 **5.6%** 로 오히려
더 좋아졌으며 AI 선정률도 100% 로 돌아왔다. 다른 지표의 소폭 변동(광고성 수식 10.1→11.5,
실용어 212→198)은 표본 10개·온도 0.7 의 노이즈 범위로 본다.

## 3-2. 다양성의 진짜 병목은 프롬프트가 아니라 후보 풀이다

arm ④ 에서도 **대분류 1종 코스가 50%** 로 남았다. 프롬프트를 어떻게 쓰든 더 못 내려간다.
`_search_pool` 이 실제로 만들어 주는 후보 풀을 열어 보면 이유가 분명하다.

| 페르소나 | 후보 수 | 후보 풀의 대분류 구성 |
|---|---:|---|
| P02 문화생활·종로 | 10 | **문화 10** |
| P08 쇼핑·강남 | 10 | **쇼핑 10** |
| P10 역사·종로 | 10 | **문화 10** |
| P01 힐링·종로 | 10 | 자연 9 · 역사 1 |
| P04 놀거리·홍대 | 10 | 쇼핑 4 · 문화 2 · 자연 2 · 명소 1 · 체험 1 |

세 페르소나는 **후보 10곳이 전부 같은 대분류**다. LLM 에게 섞으라고 아무리 지시해도
섞을 재료가 없다. 실제로 후보가 다양했던 P04 는 arm ③·④ 에서 3~4종을 만들어 냈다.

원인은 구조적이다. `_search_pool` 은 목적 칩을 `pt_<slug>` 하드필터로 걸고, 그 목적 태그는
빌드 단계에서 `PURPOSE_SEED[coarse_category]` 로부터 파생된다. **목적과 대분류가 같은
축에서 나오므로**, 목적으로 거르면 대분류가 자동으로 한 종류로 수렴한다.

### 다음 레버 (미적용)

프롬프트는 한계에 도달했다. 더 다양한 장소를 내려면 **후보 풀 구성**을 손대야 한다.

- **(A) 대분류 상한** — 최종 후보에서 한 대분류가 차지하는 비율에 상한(예: 60%)을 두고,
  남는 자리는 같은 권역의 다른 대분류로 채운다. `_search_pool` 의 "권역만" 단계를
  폴백이 아니라 항상 섞어 넣는 형태.
- **(B) `_geo_rerank` 에 MMR 항 추가** — 이미 뽑힌 후보와 대분류가 같으면 점수를 깎는다.
  다만 풀 자체가 단일 대분류면 (A) 없이는 효과가 없다.

둘 다 **목적 필터의 의미를 바꾸는 변경**이다 — "쇼핑을 고른 사용자에게 쇼핑 아닌 곳을
얼마나 섞어 줄 것인가"는 제품 판단이 필요하다. 그래서 이번 측정에는 넣지 않았다.

## 4. 종합

| | 데이터 개선 | 프롬프트 개선 |
|---|---|---|
| 지리적 응집 | **주효** (−62%) | 보조 (−3.7pp) |
| 문체·실용성 | 무효 | **주효** (수식 −56%, 실용어 +44%) |
| 저가치 장소 배제 | **주효** | — |
| 검색 회수율 | 개선 (90→100%) | — |
| 대분류 다양성 | 무효 | **한계 도달** (60→50%, 더 못 내림) |

두 작업은 **서로 겹치지 않는 축**을 개선했다. 데이터는 "무엇을 고르는가", 프롬프트는
"어떻게 쓰는가"를 각각 담당했고, 분리 측정이 이를 확인했다.

**남은 과제는 대분류 다양성 하나**인데, 3-2 에서 보듯 이건 프롬프트로 풀 수 있는 문제가
아니다. 후보 풀이 단일 대분류로 수렴하는 구조를 바꿔야 하고, 그건 "목적 칩을 얼마나
느슨하게 해석할 것인가"라는 제품 결정을 먼저 요구한다.

### 운영 반영

측정 후 옛 컬렉션(865건)을 삭제하고 `seoullo_v2` → `seoullo` 로 이름을 바꿨다.
Chroma 는 `collection.modify(name=...)` 로 **재임베딩 없이** 이름만 교체할 수 있다.
`chroma_collection` 기본값이 `seoullo` 이므로 설정 변경이나 env 없이 서비스가 새 데이터를
바로 쓴다. 삭제 직전 `data/chroma` 전체를 백업해 뒀다.

이 조치로 **arm ① 은 더 이상 재실행할 수 없다**(결과 JSON 은 `ab_artifacts/` 에 보존).

## 부록 — 재현 방법

```bash
# arm ①  (옛 컬렉션 + 옛 프롬프트)
cp ab/course.OLD.py app/graph/nodes/course.py
cp ab/schema.OLD.py app/features/course/schema.py
CHROMA_COLLECTION=seoullo    python ab/run_arm.py ab/arm1.json

# arm ②  (새 컬렉션 + 옛 프롬프트)
CHROMA_COLLECTION=seoullo_v2 python ab/run_arm.py ab/arm2.json

# arm ③  (새 컬렉션 + 새 프롬프트)
cp ab/course.NEW.py app/graph/nodes/course.py
cp ab/schema.NEW.py app/features/course/schema.py
CHROMA_COLLECTION=seoullo_v2 python ab/run_arm.py ab/arm3.json

# arm ④  (새 컬렉션 + 다양성 규칙 수정 = 현재 소스)
cp ab/course.FIX.py app/graph/nodes/course.py
CHROMA_COLLECTION=seoullo_v2 python ab/run_arm.py ab/arm4.json

python ab/analyze.py ab/arm1.json ab/arm2.json ab/arm3.json ab/arm4.json
python ab/detail.py arm1 arm2 arm3 arm4
```

컬렉션 정리 후에는 `seoullo` 가 새 데이터(816건)를 가리키므로 **arm ① 은 재실행할 수 없다.**
②·③·④ 는 `CHROMA_COLLECTION` 없이 그대로 재현된다.

### 측정의 한계

- **표본 10개.** 페르소나별 차이가 커서 소수점 단위 변화는 노이즈로 봐야 한다.
  방향성이 뚜렷한 지표(200m 스톱쌍, 광고성 수식, 실용어)만 결론에 썼다.
