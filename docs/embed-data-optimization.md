> 작업일: 2026-07-28
> 대상: `data/embed/places.json` (코스 RAG 의 유일한 원천)
> 결과: **816곳 → 807곳**, 목적 태그 전면 재설계, 신규 필드 1개

## 0. 왜 했는가

칩으로 코스를 만들면 **선택한 목적과 무관한 장소가 나오거나, 같은 목적을 고르면 늘 비슷한
결과가 나왔다.**

| 문제 | 실측 |
|---|---|
| 핫플레이스가 개별 편집숍으로 채워짐 | 핫플 307곳 중 **244곳**이 개별 매장·백화점 |
| 맛집 탐방 목적이 빈약하고 오분류 | 73곳(전체의 9%), 그중 **17곳**이 갤러리·방송국 사옥 |
| 체험·놀거리 태그에 기준이 없음 | 박물관 51곳 중 **20곳(39%)**에만 붙음 — 나머지 31곳이 빠진 이유 없음 |
| 장소가 조용히 유실됨 | 이름 앞뒤 공백 **39곳(4.8%)** → 화이트리스트 매칭 실패 |

마지막 것은 특히 치명적이었다. 실행 추적에서 **LLM 이 6곳을 정확히 골랐는데 최종 코스에는
4곳만 남았다.** 후보 이름이 `'탈방 '`, `'안녕인사동 '`(후행 공백)인데 LLM 은 당연히 공백 없이
답해서, `select_places_node` 의 화이트리스트가 통과시키지 못하고 버렸다.

해결 방법: 청킹 전에 파싱하는 코드 추가

### 방향

**"고정된 장소는 목적에 따라 행동이 바뀌므로 여러 역할에 중복 소속될 수 있다."**
경복궁은 문화·예술이면서 관광 명소이고 체험이기도 하다. 누구와 무엇하러 가느냐에 따라
거기서 하는 일이 달라지기 때문이다.

**예외는 쇼핑과 식사뿐이다. 이 둘은 단일 역할에 국한된다.**
편집숍은 쇼핑하러 갈 때만 의미가 있고, 식당은 밥 먹을 때만 의미가 있다.
그래서 쇼핑은 목적 태그를 좁히고, 식사는 목적 칩에서 아예 분리했다.

## 1. 검색을 결정하는 것은 무엇인가 — 재태깅의 전제

작업 전에 확인한 사실. **`category` 도 `coarse_category` 도 검색에 관여하지 않는다.**

| 필드 | 역할 | 검색 필터 |
|---|---|---|
| **`purpose_tags`** | 목적 칩 매칭 (`pt_<slug>` 불리언 메타로 전개) | ✅ **하드 필터** |
| **`area`** | 권역 칩 매칭 | ✅ 하드 필터 |
| `coarse_category` | LLM 다양성 규칙용 표시 | ❌ |
| `category` | 프롬프트 표시 + 체류시간 폴백 | ❌ |

`_search_pool()` 이 만드는 실제 Chroma `where` (실측 덤프):

```json
{"doc_type":"place", "area":"종로·중구",
 "$or":[{"pt_culture":{"$eq":true}}, {"pt_food":{"$eq":true}}]}
```

즉 **"어떤 장소가 후보에 오르는가"는 오직 `purpose_tags` 와 `area` 가 정한다.**
그래서 이번 작업은 카테고리 재분류가 아니라 **목적 태그 재태깅**이 핵심이 됐다.

## 2. 무엇을 어떻게 바꿨는가

### 2-1. 이름 정규화 — 39곳

원천에 일반 공백·탭·전각공백(U+3000)이 섞여 있었다.

```
' NR CERAMICS'   '가회민화박물관　'   '국립항공박물관\t'   '경복궁 돌담길 '   '리움 미술관 '
```

**데이터에서 정리 + 코드 2곳에 방어막**을 걸었다.

| 위치 | 효과 |
|---|---|
| `places.json` | 39곳 정리 |
| `app/rag/ingest.py` | 색인 진입점에서 `.strip()` — 앞으로 오염이 들어와도 차단 |
| `app/graph/nodes/course.py::_cand()` | 읽을 때 `.strip()` — 재색인 전에도 즉시 해결 |

**효과**: LLM 이 고른 장소가 유실되지 않는다 → `place_count` 칩이 실제로 지켜진다.

### 2-2. 중복 병합 — 8쌍

좌표 근접 + 이름 유사 + 본문 문맥 3축으로 검출했다. 213쌍 후보에서 **포함관계(권역 ⟷ 내부
콘텐츠)를 걸러내 28쌍**으로 좁힌 뒤, 실제 같은 장소 8쌍을 병합했다.

> 포함관계를 제외한 이유: **명동 ⟷ 명동성당(95m)은 서로 다른 콘텐츠다.**
> 둘 다 유효한 스톱이고, 막으면 오히려 코스가 빈약해진다.
> 반면 남산서울타워 ⟷ N서울타워(3m)는 같은 장소가 두 레코드로 들어간 것이다.

| 정본 | 흡수 | 병합에서 건진 것 |
|---|---|---|
| 남산서울타워 | N서울타워 | 운영시간 **0~24 → 10~22**(정확), `isFilming`+「싱글인서울」 |
| 북악스카이웨이 팔각정 | 북악스카이웨이 북악팔각정 | 문화·예술 태그 |
| **광화문광장** | 광화문광장(광화문) | 이름 통일, 문화·예술 태그 |
| 용리단길 | 용산 용리단길 | `areaName='용리단길'` |
| 서울어린이대공원 | 어린이대공원 | `areaName='어린이대공원'` |
| **노들섬** | 노들섬(2028년 완공예정) | **좌표 교체** 126.9378 → **126.9580** |
| **하늘공원** | 하늘공원(월드컵공원내) | 운영시간 **0~24 → 5~22** |
| 인왕산(무무대 전망대) | 인왕산 | 태그 정리 |

병합 규칙: 태그는 **합집합**, `areaName`·`isFilming`·`contentTitle` 은 있는 쪽 보존,
운영시간은 `hours_known=True` 이면서 0~24 가 아닌 구체적 값 우선.

노들섬·하늘공원·인왕산은 **이름이 같은데 좌표가 526m~1,785m 떨어져 있던 데이터 오류**이기도
했다.

기존에는 박물관 51곳 중 20곳(39%)에만 붙어 있었는데, 그 20곳이 선택된 기준이 없었다.
원천 설명문에 '체험' 이라는 단어가 우연히 들어간 곳만 태그가 붙은 형태였다.

**`데이트` 를 전 카테고리에 넣은 이유** — 데이트는 어디서든 가능하다.
결과적으로 587곳(73%)이 되어 하드필터로서의 기능은 잃지만, 목적 칩은 필터 외에
**검색 쿼리 확장어**("데이트 분위기 야경 감성")와 **LLM 렌즈**로도 작동하고
그 두 경로는 그대로다. 의도된 결과다.

### 3-2. 쇼핑 재태깅 — 단일역할이라 덮어쓰기 (224곳)

**삭제가 아니라 목적을 좁혔다.** 쇼핑 칩을 고른 사용자에게는 여전히 298곳이 다 나온다.
문제는 개별 편집숍·백화점이 `핫플레이스` 태그를 달고 있어 **핫플 검색에 딸려오던 것**이다.

| 버킷 | 개수 | 이전 핫플 비율 | 최종 태그 |
|---|---|---|---|
| 개별 매장 (논픽션 한남·SISAO·엠크라프트…) | 143 | **91%** | `["쇼핑"]` |
| 백화점·상가류 (신세계·갤러리아·코엑스몰·면세점…) | 39 | **85%** | `["쇼핑"]` |
| 전통시장 (경동시장·망원시장·통인시장…) | 27 | 85% | `["쇼핑", "관광 명소"]` |
| 거리·골목 (용리단길·연무장길·쌈지길…) | 15 | 94% | 현행 유지 |

- **백화점·면세점은 쇼핑이지 관광 코스가 아니다** → `["쇼핑"]` 만
- **전통시장은 관광객에게 관광 체험이다** → `관광 명소` 추가
- **거리·골목은 권역 대표 성격** → 핫플 유지가 맞음

버킷 분류 기준 (이름 패턴):
```

전통시장       "시장" 포함 & 백화점·면세점·몰·아울렛·상가류 아님
백화점·상가류   백화점 / 면세점 / 몰 / 아울렛 / 쇼핑센터 / 지하상가 / 플라자 / 타운 / 마트 / 상가
개별 매장      나머지
```

### 3-3. 맛집 탐방 칩 제거 — 73곳에서 태그 삭제

식사를 **목적 칩에서 분리해 별도 축(아침 10시 / 점심 13시 / 저녁 19시 선택)**으로 올렸다.

이유:
- 커버리지가 73곳(9%)뿐이고, 그중 **17곳이 갤러리·방송국 사옥 오분류**
  (롤파크·페이스갤러리·BLUE SQUARE·상암동 MBC 신사옥·63스퀘어…)
- 실질 후보는 56곳까지 떨어진다
- **`data/meal_cache/` 에 이미 1,234곳의 식당 데이터가 있다** — `places.json`(807곳)의 1.5배
- 지금까지 이 1,234곳을 끼니 슬롯 추천 3곳에만 쓰고 있었다

식사 시각의 재고는 실측으로 확인했다:

| 끼니 | 그 시각 영업 중 |
|---|---|
| 아침 10:00 | 367곳 |
| 점심 13:00 | 1,075곳 |
| 저녁 19:00 | 997곳 |

> `app/core/scheduler.py` 의 *"아침 영업 식당이 사실상 없다"* 주석은 **틀렸다.**
> 근거가 *한식당 18곳 표본*이었다. 전체 1,234곳 기준 09시 이전 개점이 124곳(10.3%),
> 10시까지 누적 367곳이다. 한남북엇국·설담재설렁탕·금수복국·제주미향해장(24시간)과
> 07:30 개점 브런치 카페 다수가 있다.

**핫플레이스는 권역당 5~10곳이 자연스러운 목적이다.** 한 동네에 "요즘 뜨는 곳"이 20곳씩
있지는 않다. 문화·예술 362곳처럼 많을 수가 없다.

## 4. K-콘텐츠 촬영지 — 카테고리로 나누지 않고 정보로만 전달

`category = "K-콘텐츠 촬영지"` 인 30곳은 **카테고리가 아니라 부가 속성**이다.
경의선숲길은 공원인데 category 가 K-콘텐츠라 원래 성격이 지워져 있었다.

**결정: 30곳을 개별 카테고리로 재분류하지 않는다.** 대신 `isFilming` / `contentTitle`
(이미 별도 필드로 존재)을 LLM 에 **정보로만** 넘기고, `ragText` 에 한 줄을 추가했다.

```
자하문터널은 종로·중구에 위치한 청운동과 부암동을 잇는 터널로 …
드라마·영상 「기생충」 촬영지로 알려진 곳이에요.        ← 추가
어울리는 목적: 관광 명소, 데이트, 자연·힐링
```

> **작업 중 사고 하나**: K-콘텐츠 문구를 넣을 때 정규식 `[^)\n]*` 이 줄 끝까지 삼켜
> **19곳의 본문이 잘렸다.** 원본에서 복구한 뒤 치환이 아니라 한 줄 추가 방식으로 다시
> 적용했고, 목적·K-콘텐츠 줄을 제외한 본문이 원본과 100% 일치하는지 재검증했다.

## 5. `ragText` 동기화 — 임베딩 품질에 직결

`ragText` 안에 `어울리는 목적: …` 줄이 있는데, **807곳 중 564곳(70%)이 옛 태그를 담고
있었다.** 이대로 임베딩하면 스테일 정보가 벡터에 그대로 반영된다.

- 태그를 **뺀** 곳: 본문은 여전히 "핫플레이스" 라고 말한다 → 검색 랭킹이 어긋남
- 태그를 **더한** 곳: 본문에 "체험" 이 없어 체험 쿼리에서 유사도가 낮게 잡힘

784곳의 목적 줄을 `purpose_tags` 와 동기화했다. 최종 불일치 **0곳**.

좌표가 **완전히 동일한** 장소를 묶는 그룹 키. 34개 그룹 74곳.

```
"감사의 정원": [광화문광장, 감사의 정원, 광화문광장 해치마당]
```
