# 배포 아키텍처 — Vercel 프로덕션 ↔ AI 서버 연결

> 현재 서울로(strangemap)는 **Vercel에 배포된 Next.js BFF** 단일 구조라 로컬 개발 때 별도 서버가
> 필요 없었다. 코스 생성 기능만 **RAG + LangGraph 기반 AI 서버**(FastAPI)로 분리하면서,
> 기존 Vercel 프로덕션과 AI 서버를 **어떻게 연결할지**를 정리한다.
> (AI 서버의 실제 호스팅 방식 — 컨테이너/서버리스 — 은 아직 미확정. 이 문서는 **연결 구조**와
> **역할 분리**를 정의한다.)
>
> 2026-07-24 갱신: 코스 파이프라인이 **방문 순서까지 서버가 확정**하도록 바뀌었다
> (`app/core/scheduler.py`, `app/graph/nodes/course.py`). 아래 4·5장이 이를 반영해 갱신됨 —
> 옛 버전 기준 "순서는 프론트가 계산" 문구는 더 이상 유효하지 않다.

---

## 1. 전체 구조

```
┌────────────┐      ┌─────────────────────────┐      ┌──────────────┐
│  브라우저   │─────▶│  Vercel (Next.js BFF)   │─────▶│   AI 서버    │
│ (클라이언트)│◀─────│  현재 프로덕션 그대로    │◀─────│  (FastAPI)   │
└────────────┘      └─────────────────────────┘      └──────┬───────┘
                                                            │
                                                     ┌──────▼───────┐
                                                     │   Vector DB  │
                                                     │ (임베딩) + DB │
                                                     └──────────────┘
```

- **브라우저는 AI 서버를 직접 호출하지 않는다.** 항상 Vercel BFF를 거친다.
- **BFF가 AI 서버로 프록시**한다 — 코스 생성 요청만 AI 서버로 넘기고 응답을 그대로 전달.
- AI 서버는 외부에 직접 노출하지 않고 **BFF만 접근**하도록 둔다 (`app/main.py`의
  `X-Internal-Token` 미들웨어로 검증 — `AI_SERVER_TOKEN` 공유 시크릿).

## 2. 연결 방식 — HTTP 프록시

Vercel과 AI 서버 사이에 특별한 통합은 없다. **BFF 서버 라우트에서 HTTPS 호출**만 한다.

```
브라우저 ──(same-origin)──▶ Vercel BFF route ──(fetch, HTTPS)──▶ AI 서버 엔드포인트
                                   │
                              AI_SERVER_URL (env)
                              X-Internal-Token (env, AI_SERVER_TOKEN 과 동일값)
```

- BFF의 서버 사이드 라우트(예: Route Handler / API Route)에서
  `fetch(process.env.AI_SERVER_URL + "/agent/chat", { method: "POST", ... })`.
- 응답 스키마는 `docs/context-for-strangemap.md` 의 `/agent/chat` 계약을 그대로 사용.
- 스트리밍이 필요하면 AI 서버의 `/agent/chat/stream`(SSE)을 BFF가 그대로 파이프.

## 3. 이 구조를 쓰는 이유 (BFF 원칙 유지)

| 이유 | 내용 |
|---|---|
| **API 키 보호** | `SEOUL_API_KEY`, 솔라 키 등은 AI 서버·BFF의 서버 env에만. 브라우저에 절대 노출 안 됨 |
| **CORS 단순화** | 브라우저는 same-origin(Vercel)만 호출 → CORS 이슈 없음 |
| **인증·레이트리밋 집중** | 로그인·요청 제한을 BFF 한 곳에서 처리 |
| **AI 서버 은닉** | AI 서버는 내부망/토큰 뒤에 두고 BFF만 접근 |

## 4. 역할 분리 — AI 서버가 하는 일 / 프론트가 하는 일

> 이 경계가 지금까지 두 번 바뀌었다: (초기) 서버는 장소·이유만 → (중간) 서버는 장소·이유 +
> 시간표만, 순서는 프론트 → **(현재) 서버가 장소·이유·방문 순서·시간표까지 전부 확정**하고,
> 프론트는 그 순서대로 **실제 도로 경로(폴리라인) 렌더링만** 담당.

| 담당 | AI 서버 (lewisai) | 프론트 (strangemap) |
|---|---|---|
| 장소 선정 · 선정 이유 · activities | ✅ | ❌ |
| **방문 순서** | ✅ (아래 4-1 참고) | ❌ (재정렬 금지) |
| 시간표(시각·끼니 슬롯·체류시간) | ✅ (`app/core/scheduler.py`) | ❌ |
| 혼잡도 · 주변 식당/행사 | ✅ | ❌ |
| **실제 도로 기반 경로(폴리라인) 렌더링** | ❌ | ✅ |
| **실거리·실이동시간(내비게이션 API 기준)** | ❌ | ✅ |

### 4-1. 방문 순서는 어떻게 확정되나

- **시간 범위(시간표) 요청** — `chips.time_window` 또는 `time` 칩이 있으면 `build_schedule()`이
  장소 수(3~6곳)에 대해 **순열 전수 탐색**을 돌려, "운영시간 안에 앉힌 장소 수 최대 →
  직선거리 기준 이동 최소"인 순서를 고른다. 이 순서가 곧 응답 `stops[]` 배열 순서다.
- **시간 범위 없는 요청** — `select_places_node`가 LLM에게 "하루 안에서는 자연스러운 방문
  흐름 순서로 나열"하도록 지시해 순서를 정한다. 순열 최적화는 안 하지만 순서 결정 주체는
  여전히 서버다.
- 두 경우 모두 **`stops[]` 배열에 담긴 순서가 최종 방문 순서**다. 프론트는 이 순서를
  그대로 렌더링에 쓰면 되고, 재정렬하면 안 된다.

### 4-2. 프론트에 남는 일 — 왜 "경로 로직만"인가

서버가 주는 `travel_min`/`travel_mode`(시간표 요청 한정)는 **직선거리 기반 추정치**다
(`app/core/scheduler.py` 상단 docstring: "실경로/폴리라인은 여전히 strangemap 프론트
담당"). 서버는 지도 API를 호출하지 않는다. 따라서 프론트가 할 일은:

1. 서버가 준 `stops[]` 순서 + `lat`/`lng`를 그대로 입력으로 받아
2. 지도 SDK/내비게이션 API로 **실제 도로를 따르는 폴리라인과 실거리·실소요시간**을 계산·렌더링

즉 "어디를, 왜, 어떤 순서로 갈지"는 서버가 끝내고 프론트는 "그 순서를 지도 위에 어떻게
그릴지"만 담당한다.

## 5. 연결 시 지켜야 할 계약

1. **응답 스키마 동결** — `CourseResponse`/`CourseStop` 필드는 추가만, 제거·의미 변경 금지.
2. **키는 서버 env에만** — BFF·AI 서버 양쪽 다 코드 하드코딩 금지.
3. **AI 서버 직접 노출 금지** — 프로덕션에서 브라우저가 AI 서버 URL을 알 필요 없음.
4. **순서 재정렬 금지** — 서버가 확정한 `stops[]` 순서를 프론트가 다시 계산·변경하지 않는다.
   프론트는 그 순서 위에서 실제 경로(폴리라인)만 그린다.

## 6. 환경별 연결

| 환경 | Vercel BFF | AI 서버 | `AI_SERVER_URL` |
|---|---|---|---|
| **로컬 개발** | `next dev` | `uvicorn app.main:app --reload --port 8800` | `http://localhost:8800` |
| **프로덕션** | Vercel 배포 | (호스팅 미확정 — 별도 결정) | 배포된 AI 서버 URL |

- 로컬에선 AI 서버를 `uvicorn`으로 띄워 BFF가 `localhost:8800`으로 호출.
- 프로덕션 AI 서버 호스팅 방식은 이 문서 범위 밖 — 결정되면 `AI_SERVER_URL`만 교체하면 됨.

## 7. 미결정 (추후 결정)

- **AI 서버 프로덕션 호스팅** — 컨테이너 상시 / 컨테이너 scale-to-zero / 서버리스 중 선택.
- **DB** — 임베딩 벡터 스토어(현재 로컬 Chroma sqlite) + 사용자/코스 데이터 저장소 구성.
- **AI 서버 인증 방식** — 현재 공유 시크릿 헤더(`X-Internal-Token`) 방식. 서명 기반/내부망
  전환 여부는 추후 결정.
